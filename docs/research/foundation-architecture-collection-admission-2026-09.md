# Foundation-architecture collection admission — 2026-09

- **Authority:** owner’s direct request to build a strong modular foundation, vet established repositories and services, and avoid rebuilding mature capabilities (2026-09-23).
- **Purpose:** select a reversible identity/authentication foundation and integration seams for the proposed authority, B2B consulting, and private client-workspace platform. This is research and architecture planning only; it does not install, adopt, deploy, sign up for, or contact any provider.
- **Source scope:** current local planning corpus; bounded read-only inspection of two known owner project roots for reusable patterns; public GitHub REST metadata/content for `supabase/auth`, `better-auth/better-auth`, `nextauthjs/next-auth`, `ory/kratos`, `keycloak/keycloak`, `zitadel/zitadel`, `authelia/authelia`, and `logto-io/logto`; up to two Stripe Directory discovery queries for service alternatives.
- **Access boundary:** local read-only commands and documented public GitHub/Directory read interfaces only. No private repository access, credentials, cloning, package installation, source-code execution, browser automation, authentication, CAPTCHA handling, provider signup, or network writes.
- **Accepted fields:** public repository identity, license text/SPDX, README/docs statements, release/maintenance/security-policy/workflow metadata, declared runtime/deployment shape, and local dependency/configuration names only.
- **Prohibited fields:** source code beyond bounded configuration/manifest inspection, secrets, customer/prospect data, contact data, account data, operational credentials, private project details, and claims inferred from stars or marketing copy.
- **Destination / retention:** bounded raw JSON/text evidence under `docs/research/foundation-architecture-evidence-2026-09/`, plus an architecture plan, ADR, and decision matrix in this repository. Retain with the September 2026 research corpus until superseded/archived.
- **Limits:** ≤8 external repositories; ≤12 GitHub requests per repository; ≤2 Directory queries; ≤2 local project roots; 90 seconds per batch; no retry after access-control, authentication, rate-limit, or policy block; ≤2 MB per response.
- **Success criteria:** each candidate is classified by primary-source license, operational shape, security/maintenance evidence, compatibility with the private-data contract, and explicit unknowns. A final recommendation must preserve a no-adoption state until a real website-repository spike passes its negative controls.
- **Stop conditions:** ambiguous license, access restriction, unexpected sensitive data, source-policy conflict, inability to establish project boundary, incompatible data/control model, or a candidate requiring unbounded code review.
