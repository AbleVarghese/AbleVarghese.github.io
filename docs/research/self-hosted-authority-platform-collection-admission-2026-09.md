- **Authority:** owner’s direct request: “I want to not depend on managed services. Find the very best open source path. I have macmini server to host.” (2026-09-23).
- **Purpose:** replace the earlier managed-service comparison with a self-hosted, source-controlled path for the current public profile site and a later protected operations surface. This is research and architecture planning only.
- **Source scope:** current repository; the public owner repository `AbleVarghese/AbleVarghese.github.io`; public GitHub REST metadata and bounded license/README/deployment-manifest content for `better-auth/better-auth`, `supabase/supabase`, `caddyserver/caddy`, `coollabsio/coolify`, `vercel/next.js`, `drizzle-team/drizzle-orm`, `postgres/postgres`, and `umami-software/umami`.

No cloning, package installation, source execution, container start, deployment, account creation, credential use, private-repository access, browser automation, or network write.

The only personal-data purpose is locating the already owner-published public profile-site repository; no résumé, LinkedIn, contact, client, or prospect content is collected.
- **Prohibited fields:** secrets, configuration values, private project content, source code other than bounded manifests/configuration needed to identify the runtime, operational credentials, customer/prospect data, and values inferred from popularity or marketing copy.
- **Destination / retention:** raw source receipts under `docs/research/self-hosted-authority-platform-evidence-2026-09/`; a research synthesis, decision matrix, and amended architecture/ADR records in this repository. Retain with the September 2026 research corpus until superseded or archived.
- **Limits:** ≤8 external repositories; ≤8 GitHub requests per repository; ≤90 seconds per batch; one SSH capacity probe plus one different diagnostic only if the first cannot establish reachability; no retry after an access-control, authentication, policy, or rate-limit block; ≤2 MB per response.
- **Success criteria:** identify whether the current website is deployable source or static content; classify each candidate by direct license, self-host operation, fit with the private-core contract, and runtime cost; select only a staged architecture that does not add a capability before a real workflow requires it.
- **Stop conditions:** access control, source-policy conflict, ambiguous license, unexpected sensitive data, unreachable or unmeasured server capacity, a candidate requiring an unbounded code audit, or a design that introduces a managed application/data dependency.
